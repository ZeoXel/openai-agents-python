# 常见的智能体模式

本文件夹包含了不同常见智能体模式的示例。

## 确定性流程

一个常见的策略是将任务分解为一系列较小的步骤。每个任务可以由一个智能体执行，并且一个智能体的输出用作下一个智能体的输入。例如，如果你的任务是生成一个故事，你可以将其分解为以下步骤：

1. 生成大纲
2. 生成故事
3. 生成结尾

这些步骤中的每一个都可以由智能体执行。一个智能体的输出用作下一个智能体的输入。

查看 [`deterministic.py`](./deterministic.py) 文件以了解相关示例。

## 移交和路由

在许多情况下，你会有专门的子智能体来处理特定任务。你可以使用移交功能将任务路由到正确的智能体。

例如，你可能有一个前线智能体接收请求，然后根据请求的语言移交给专门的智能体。
查看 [`routing.py`](./routing.py) 文件以了解相关示例。

## 智能体作为工具

移交的思维模型是新智能体"接管"。它看到之前的对话历史，并从那时起拥有对话的控制权。然而，这不是使用智能体的唯一方式。你也可以将智能体用作工具 - 工具智能体独立运行，然后将结果返回给原始智能体。

例如，你可以将上面的翻译任务建模为工具调用：不是移交给特定语言的智能体，而是将智能体作为工具调用，然后在下一步中使用结果。这使得可以同时翻译多种语言等功能成为可能。

查看 [`agents_as_tools.py`](./agents_as_tools.py) 文件以了解相关示例。

## LLM 作为评判者

如果获得反馈，LLM 通常可以提高其输出的质量。一个常见的模式是使用一个模型生成响应，然后使用第二个模型提供反馈。你甚至可以使用小型模型进行初始生成，使用大型模型进行反馈，以优化成本。

例如，你可以使用 LLM 生成故事大纲，然后使用第二个 LLM 评估大纲并提供反馈。然后你可以使用反馈来改进大纲，并重复直到 LLM 对大纲满意为止。

查看 [`llm_as_a_judge.py`](./llm_as_a_judge.py) 文件以了解相关示例。

## 并行化

并行运行多个智能体是一种常见模式。这对于延迟（例如，如果你有多个不相互依赖的步骤）和其他原因（例如，生成多个响应并选择最佳响应）都很有用。

查看 [`parallelization.py`](./parallelization.py) 文件以了解相关示例。它并行运行翻译智能体多次，然后选择最佳翻译。

## 护栏

与并行化相关，你通常希望运行输入护栏以确保智能体的输入有效。例如，如果你有一个客户支持智能体，你可能希望确保用户不会试图请求数学问题的帮助。

你完全可以在不使用任何特殊 Agents SDK 功能的情况下通过并行化来实现这一点，但我们支持一个特殊的护栏原语。护栏可以有一个"触发器" - 如果触发器被触发，智能体执行将立即停止，并且会引发 `GuardrailTripwireTriggered` 异常。

这对延迟非常有用：例如，你可能有一个非常快的模型运行护栏和一个慢的模型运行实际智能体。你不想等待慢模型完成，因此护栏让你可以快速拒绝无效输入。

查看 [`input_guardrails.py`](./input_guardrails.py) 和 [`output_guardrails.py`](./output_guardrails.py) 文件以了解相关示例。
